Guide

The editor

Where scenes, prefabs, materials, effects and visual scripts are made. Everything you change can be undone, and Play runs the game right there.

The panels

PanelWhat it's for
OutlinerEvery object in the scene, as a tree. Click to select (Ctrl and Shift for more than one), drag one onto another to put it under it, double-click or F2 to rename, right-click for more. The search box at the top filters by name. Click the scene's own row to edit its lighting and sky.
Scene viewThe world, to look round and arrange. Its tabs also hold the Game view (what the game's camera sees, and where UI is arranged), and any visual scripts, VFX graphs, audio graphs and prefabs you open.
InspectorWhat's selected: its name, transform and components, with all their settings. Add components here.
AssetsThe project's Assets folder: scenes, prefabs, materials, textures, models, sounds, fonts, scripts, visual scripts, VFX graphs and audio graphs.
ConsoleMessages from the editor and the game: Log.Info, warnings, errors, and build errors in your C# code. Double-click an error to open the code at its line.

Panels can be dragged to rearrange them and shown or hidden from the View menu; View › Reset Layout puts them back. View › Bigger Interface (Ctrl+=) scales the whole editor.

Arranging things

Click an object in the scene to select it. W, E and R switch between moving, rotating and scaling, with handles to drag; the toolbar in the corner of the view has the same tools, and whether they work in world or local directions. Hold Ctrl while dragging to snap (or set snapping up in Edit › Snapping). Exact values go in the inspector's Transform.

Making things

The Create menu (or the + in the outliner) makes objects: an Empty object, a Cube, Sphere or Plane, a Sun or Point Light, a Camera, and UI: a Canvas with Panels, Text, Images and Buttons. New objects go where the view is looking (at the point it orbits round).

Shapes from the Create menu are only drawn. To make one solid, add a collider: Box Collider, Sphere Collider, Capsule Collider or Mesh Collider. Add a Rigidbody as well for physics to move it.

Dragging a model (.gltf, .glb, .fbx, .obj) or a prefab from the Assets panel into the scene puts it there. Dragging a texture onto an object paints its material with it; a material, gives it that material.

The inspector

Components are what objects do. Add Component lists the engine's (rendering, physics, audio, UI, networking, effects…) and your game's own, with a search box. Typing a name that isn't there offers New Script, which writes a C# component of that name, builds it and adds it.

Each component's ⋯ menu moves it up or down or removes it. Settings are edited by dragging numbers sideways or typing in them, picking colours, choosing from lists, and filling slots:

  • File slots (a texture, material, prefab, sound, font, visual script, VFX graph, audio graph): click to pick from the project's files, or drag one in from Assets.
  • Object slots (another object, or one of its components): click to pick from the scene's objects that fit, or drag one in from the outliner. While you drag a row out of the outliner, the inspector keeps showing what you had selected, so you can drop it there.

Select several objects to edit them together: values that differ show a dash, and whatever you set goes on all of them.

Assets

Right-click in the Assets panel to make a New Folder, New Scene, New Material, New Script, New Visual Script or New VFX Graph. Double-click to open: a folder, a scene, a prefab (in its tab), a graph (in its tab), or a script (in your code editor). F2 renames, and things using a file keep using it under its new name. Drag files into folders to move them.

Files added to the folder from outside the editor (a sound, a model, a texture) show up by themselves. Changed materials and graphs are saved as you edit them; scenes are saved with Ctrl+S.

Prefabs

A prefab is a reusable object (with everything under it) saved in a file: a player, a pickup, a piece of scenery. Make one by dragging an object from the outliner into the Assets panel, or with Make Prefab on its right-click menu.

  • Double-click a prefab to open it in a tab of its own, shown alone and lit. The outliner and inspector then edit the prefab, with its own undo, and it's saved as you change it.
  • Back to Scene returns to the scene, and every copy of the prefab in it is updated.
  • A copy in the scene can be changed by itself. Apply to Prefab (right-click it in the outliner) saves those changes to the prefab, and Revert to Prefab throws them away.
  • To put a copy in the scene, drag the prefab in, or use Add to Scene from its menu.

Playing

Play (Ctrl+P) runs the open scene in the Game view, with its components and scripts, physics and sound. Click in the view to give the game the mouse and keyboard; Shift+F1 gives them back. Pause stops time to look round. Stop puts the scene back exactly as it was before Play: anything changed while playing is thrown away.

While playing, visual script tabs show the flow lighting up as it runs, and a node that goes wrong is marked with the error.

Game code

A project's C# lives in the .csproj beside its project file, which the editor makes the first time you make a script. The editor builds it in the background:

  • when the project opens,
  • whenever you come back to the editor after changing code,
  • and with File › Rebuild Game Code (Ctrl+R).

Rebuilding keeps the scene you're editing and what's selected. If the code doesn't build, the errors go to the Console, and the scene stays open with the scripts from before.

Opening a game's .csproj directly (File › Open Project) works too: it's how a game made only in code is opened. See mixing workflows.

Project settings

File › Project Settings holds:

  • Game: its name, company and version (code reads them as Application.Name, Company and Version), and its Icon: a square picture from the Assets folder, ideally 256 × 256 or bigger.
  • Starting: the Startup Scene the project opens on and the built game starts in, and the game's code.
  • Window: how the built game's window opens (a window, maximized, or fullscreen), its size, whether it can be resized, and whether it uses Vulkan where it can or always OpenGL.
  • Physics and graphics: how many physics steps a second it runs (FixedUpdate runs that often), and how detailed the sun's shadows are.

Building the game

File › Build Game (Ctrl+Shift+B) makes the game into something to give to players, who don't need the editor or .NET to play it. Choose the systems to build for and press Build. Each goes in a folder of its own in the project's Builds folder, holding just the game's program (with .NET and the engine inside it), its Assets, and game.json with how it opens:

SystemWhat it makes
WindowsThe game's .exe, named after the game, with its icon, name, version and company in its details. Zip the folder to share it.
LinuxThe game's program, and its icon as icon.png.
macOSA .app for Macs with Apple Silicon, with its icon. Built anywhere but a Mac, it has to be signed on a Mac before it opens: codesign --force --deep -s - "My Game.app".
  • The game starts in its Startup Scene, or for a game whose code has a Game class of its own, with that.
  • Everything in the Assets folder goes with it, except the C# (that's built into the game). The open scene is saved first.
  • Building needs the .NET SDK, as building game code does. The first build for each system downloads that system's .NET runtime, so it takes a minute or two; after that a build takes seconds. A build is about 50 MB.
  • The first time the game starts on a computer, it unpacks the libraries for its window, sound and physics into a cache folder of .NET's, and uses them from there after that.
  • Files built on Windows lose the mark that says they're programs: on Linux and macOS, mark the game's program as one (chmod +x) if it doesn't start.

Lighting and sky

Click the scene's row at the top of the outliner to edit its lighting: the sky and clouds, fog, the colour of the ground light bounces off, ambient occlusion, bloom, and how far shadows reach. The sky follows the first sun: turn it lower for a sunset.

A scene can have up to 256 point and spot lights in view at once. Each part of the screen only works out the lights that reach it, so many small lights cost little.

Point and spot lights with Cast Shadows on cast shadows too, also into volumetric fog. The 16 nearest the camera get them. A light's shadow is only redrawn when the light or something near it moves, so lamps in a still room cost little. Baked lights bake their shadows from things that don't move; with Cast Shadows on, things that move cast shadows from them too (see below).

Baked lighting

Baking works out a scene's light ahead of time, so it looks better and costs almost nothing while the game runs. Things that never move get soft shadows, light bounced off what's round them, and no sky light in rooms and under things. Things that move are lit by light probes, baked at the same time, which hold the light in the space between.

  1. Tick Static on the Mesh Renderers of what never moves: walls, floors, buildings, furniture.
  2. Set each light's Mode. Its Size sets how soft its baked shadows are.
  3. Save the scene, then press Bake in the Lighting panel (View › Lighting; it starts beside the Inspector), where the bake settings are too. It bakes in the background, then saves the light in a .bake file beside the scene, and saves the scene. The panel also counts the scene's static meshes and its lights of each mode, and has the sky and environment settings.
ModeWhat it does
RealtimeWorked out every frame, so it can move and change. Its light doesn't bounce.
MixedLights things every frame, and its bounced light is baked. Good for the sun.
BakedAll baked, so it costs nothing while the game runs, however many there are. It can't move or change, and it has no highlights. It still shows in volumetric fog, and with Cast Shadows on, things that move still cast shadows from it. Good for lamps.
  • Detail is how many lightmap pixels there are to a unit of surface. More gives sharper shadows and a slower bake. If the lightmap won't fit in Max Lightmap Size, detail is lowered to fit.
  • Quality: Preview is quick but grainy; Good suits most scenes; High is the smoothest. Bounces is how many times light bounces.
  • Moving a static object, or changing a baked light, leaves the old light where it was until you bake again. Clear removes the baked light.
  • Until a scene has been baked, Baked lights light it as they're worked out, so you can see them while you build.
  • Things that move cast shadows from Baked lights that have Cast Shadows on, onto static things too: the bake keeps how much of each light reached each part of the lightmap, and where something that moves blocks one, its light is taken back out. Up to four of these lights can reach the same place; if more overlap, the dimmest only have their baked shadows, and the Lighting panel's Moving shadows says how many were left out. These shadows only cost anything while something that moves is near the light.

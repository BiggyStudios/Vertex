Guide

Multiplayer

Players find each other through Steam, or on the local network, and play together. A few components and a handful of ideas cover it, the same in C# and visual scripting.

How it works

  • One machine hosts a game (a room), and the others join it.
  • Every machine has every shared object. An object with a Network Object component that one machine makes is made on all the others too, and destroying it destroys it everywhere.
  • Each shared object has an owner: the machine that made it. A player's own machine owns their player. The owner moves it and decides about it; a Network Transform sends its moves to everyone else, who see it glide there.
  • Is Mine says whether this machine owns an object. Scripts run on every machine's copy, so anything that reads the keyboard or moves the object checks it first. Playing alone, everything is yours.
  • Network events carry everything else: a name and up to three values, sent to everyone, to everyone else, to an object's owner, or to the host.

The Network Manager

Put one Network Manager in the scene. It connects, and gives each player their own copy of the Player Prefab at a Spawn Point: the host at the first, people joining at the next ones.

Events for scripts: On Connected, On Disconnected, On Player Joined and On Player Left (with the player's name).

Set Network.GameVersion when your game starts and bump it when you release a version that plays differently: players only join rooms of the same version.

Shared objects

Players are made for you. For anything else everyone should see (a rocket, a grenade, a pickup that appears), use Network Spawn (C#: NetworkScene.Spawn(prefab, position, rotation)). The prefab should have a Network Object, and a Network Transform if it moves. This machine owns what it spawns.

An object that's only for show on one machine (a muzzle flash, sparks, a sound) doesn't need to be shared: make it locally when a network event says so.

Network events

A network event has a name, the object it's about (or none), who it goes to, and up to three values: numbers, true/false, text, vectors, colours, or shared objects.

ToGoes toFor
EveryoneEvery machine, this one includedThings everyone sees: a shot, an explosion, a score.
OthersEvery machine but this oneTelling others about something this machine already did.
OwnerThe machine that owns the objectTelling a player they were hit: their machine looks after their health.
HostThe host onlyAsking the host to decide something shared: who picked up the flag first.

An event about an object arrives at the scripts on that object (each machine's copy of it). An event about no object arrives at every script.

In C#

// Send: "Hit", about the player we hit, to its owner, with the damage and who shot.
NetworkScene.SendEvent("Hit", target, NetworkTarget.Owner, 25f, GameObject);

// Receive, in a component on the object it's about.
protected override void OnNetworkEvent(NetworkEvent e)
{
    if (e.Name != "Hit" || !IsMine) return;
    float damage = e.Values[0] as float? ?? 0f;
    GameObject? shooter = e.Values[1] as GameObject;
    Log.Info($"{e.From} hit me for {damage}");
}

// Or every event, anywhere.
NetworkScene.EventReceived += e => Log.Info($"{e.Name} from {e.From}");

In visual scripts

Send Network Event has the name, the Target it's about (empty means this object), To, and values A, B and C; tick Every Script to send it about no object. On Network Event starts when one with its name arrives, with From (who sent it) and A to C.

C# components and visual scripts get the same events, so they can be mixed.

Who decides what

Vertex trusts each machine about what it owns: the shooter's machine decides it hit, and the hit player's machine takes the damage. That keeps things simple and responsive, and suits games among friends. Things that belong to nobody (a round timer, a shared pickup) are best decided by the host: send a request to the Host, and let the host tell Everyone the result.

There's no lag compensation or server-side checking: a player with a modified game could cheat. Fine for playing with friends; worth knowing before a public release.

Useful nodes and members

  • Respawn Point / SpawnPoint.FurthestFromOthers(player): the spawn point furthest from the other players.
  • Owner Name / networkObject.OwnerName: whose an object is, to credit a kill.
  • NetworkScene.Players: every player's object; NetworkScene.Objects: every shared object.

Testing

  • Alone: just press Play. Everything is yours, and events sent to Everyone or the Owner come straight back.
  • Two on one PC: set Service to Local Network (or start with -lan), open the project in two editors (or run two copies of a built game), Play both, and connect: the first hosts, the second joins.
  • Over Steam: two PCs, each signed in to its own Steam account. Quick Match on both.

The Duel tutorial puts all of this together.

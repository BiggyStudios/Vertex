Shaders and post effects

A shader works out a colour for every pixel. There are two kinds. A surface shader goes on a material and works out how its surface looks at each point: flowing lava, a force field, a scrolling screen. A post effect goes on a camera and changes the finished picture: a colour grade, film grain, big pixels. Make either with nodes in a shader graph, or write it in GLSL. Both run in Vulkan and OpenGL alike.

Examples

A few shader graphs, as they look in the editor. Drag to pan, scroll to zoom, and hover a node to see what it does.

Shader graphs

  1. In the Assets panel, press + and choose New Shader Graph for a material, or New Post Effect Graph for a camera. It makes a .shadergraph file and opens it in a tab, already set up to show how one's made.
  2. For a material, pick the file as the material's Shader in the inspector. For a camera, Add Component › Post Effect and pick it as its Shader. Each slot only offers shaders of its own kind.
  3. Edit the graph. The Preview in the corner of the tab shows what it makes as you go: a material's on a ball (or a block or a square; drag to turn it), a post effect's on a little scene. Everything using the graph changes with it, and it's saved as you edit.

A graph ends in one output node. Everything linked into it is worked out for each pixel from where it is (its texture coordinates, its place in the world, the time), maths, noise, shapes, textures and colours. Right-click or press Space to add nodes; the node reference has every one.

The Surface node

Where a material's graph ends. An input left unlinked keeps the material's own setting, so a graph can change just the glow and leave the colour, roughness and normal map to the material.

InputWhat it is
ColorThe surface's colour.
Alpha, Alpha ClipWhere Alpha is below Alpha Clip, nothing's drawn: leaves, fences, holes. 0.5 is the usual clip.
NormalBumps, as a normal map has them. Link a Sample Normal Map.
Roughness, Metallic, SpecularAs on a material: from polished to chalky, metal or not, how much a non-metal reflects.
EmissionLight it gives off itself. Above 1, it glows and blooms.

The Material node gives the material's own settings (its colour times its texture, and so on) to build on. A Post Effect node ends a camera's graph instead: link into its Color the colour each pixel becomes. Picture reads the picture so far, anywhere on the screen.

Properties

The graph's Properties (the panel in its top-left corner) are its settings: numbers, vectors, colours, true/false and textures. Each material or effect using the graph shows them in the inspector and sets its own, so one lava graph can glow orange on one rock and green on another. A Get Property node reads one in the graph.

A node that's wrong (a Picture in a material's graph, say) is outlined red, and what's wrong shows in a box at the bottom of the tab and under the material or effect in the inspector. Until it's put right, a material is drawn its standard way and an effect is left out.

Surface shaders in GLSL

A surface shader can be written by hand, too: a .glsl file defining surface, which is given the material's look and changes what it likes. Pick the file as a material's Shader, as with a graph.

// Glowing cracks that crawl.
property color Glow = #FF6010;
property float Speed = 1 [0, 4];   // How fast the cracks crawl
property texture Cracks = "Textures/Cracks.png";

void surface(inout Surface s)
{
    float crack = sampleData(Cracks, uv + vec2(time * Speed * 0.1, 0.0)).r;
    s.emission = Glow.rgb * crack * 4.0;
    s.roughness = mix(s.roughness, 0.2, crack);
}

s starts as the material's own look. Colours in it are linear, as light is worked out in; a color setting arrives linear too.

s.What it is
color, alphaThe colour, and how solid it is.
alphaClipWhere alpha is below it, nothing's drawn. 0 to start with.
normalWhich way the surface faces, in the world.
roughness, metallic, specularAs on the material.
emissionLight it gives off.
It can readWhat it is
uvThe mesh's texture coordinates here.
worldPosition, worldNormalWhere the point is, and which way the mesh faces there (before any bumps).
viewDirectionThe way from the point to the camera.
objectPositionWhere the object's origin is.
screenPositionWhere on the screen, 0 to 1 from the top-left.
timeSeconds since the game started.
sampleColor(texture, uv)A texture's colour, made linear.
sampleData(texture, uv)A texture's values as stored: masks, heights, noise.
surfaceToWorld(sampleNormal(texture, uv, strength))A normal map's bumps, as a normal for s.normal.

Post effects in GLSL

In the Assets panel, New Post Effect makes a .glsl file that starts as a simple colour grade. A post effect is a function, effect, that's given a place on the screen and returns the colour to show there. This one makes the picture into big square pixels with fewer shades:

// Big square pixels and fewer shades: a low-resolution look.
property float Lines = 240 [60, 720];   // How many rows of pixels fill the screen
property int Shades = 6 [2, 32];        // How many levels each colour has

vec4 effect(vec2 uv)
{
    // Which big pixel this is, and the colour at its middle.
    float size = max(1.0, floor(screenSize.y / Lines + 0.5));
    vec2 cell = floor(uv * screenSize / size);
    vec3 colour = picture((cell + 0.5) * size / screenSize).rgb;

    float steps = float(Shades - 1);
    return vec4(floor(colour * steps + 0.5) / steps, 1.0);
}
It can readWhat it is
uvWhere on the screen, from 0 to 1 across and down, starting at the top-left corner.
picture(uv)The picture so far at any place on the screen, in screen colours from 0 to 1. Lighting, fog, bloom, tone mapping and anti-aliasing have all been done.
distanceAt(uv)How far from the camera what's drawn there is, in metres along its view. Very large for the sky.
screenSizeThe size of the picture in pixels, as a vec2.
timeSeconds since the game started, for things that move.

The scene view shows the game camera's post effects too, so you see the scene as the game will. The button beside the grid's in its toolbar (or View › Post Effects) turns that off and on. A camera can have several Post Effects: they run in the order they're on it, each on what the one before made.

Everything else is ordinary GLSL, in both kinds of shader: functions of your own, loops, mix, smoothstep and the rest. Each time you save the file, what uses it changes.

Settings

In GLSL, each line starting with property is a setting. It shows in the inspector of what uses the shader, and the shader reads it by its name:

property float Strength = 0.5 [0, 1];   // How strong it is
property color Tint = #FFB070;           // A warm orange
property bool Flicker = false;
property texture Bumps = normal;

After the type and name come its starting value, an optional range in square brackets (the inspector shows a slider for it), and a comment, which becomes its tooltip.

TypeWritten likeIn the inspector
float1.5A number, or a slider with a range
int4A whole number, or a slider with a range
booltrue or falseA tick box
vec2, vec3, vec4(1, 0.5, 0)A box for each part
color#FF8800, or (1, 0.5, 0, 1) from 0 to 1A colour picker
texturewhite, black, normal (a flat normal map) or "Textures/Bricks.png"A texture slot

A shader can have up to 16 settings and 4 textures. Settings changed on a material or effect are saved with it; those left alone follow the shader's starting values, so changing one in the shader changes everything that hasn't set its own.

From code

Settings can change while the game runs, to fade an effect in or make a material react to what happens:

var effect = Camera.Main!.GetComponent<PostEffect>()!;
effect.Set("Strength", 0.8f);
effect.Enabled = false;   // off for now

Material lava = GetComponent<MeshRenderer>()!.Material;
lava.Set("Glow", new Color(0.2f, 1f, 0.3f));
lava.SetTexture("Cracks", Assets.LoadTexture("Textures/Ice.png"));

Shaders load like any other file: material.Shader = Assets.LoadShader("Shaders/Lava.shadergraph"), or camera.AddComponent<PostEffect>().Shader = Assets.LoadShader("Shaders/Pixels.glsl").

A retro look

Some of the look of early 3D consoles happens as things are drawn, so a post effect can't do it alone. The scene's Lighting & Sky has a Retro section for that part:

SettingWhat it does
Vertex SnappingCorners of meshes snap to a grid this many rows high on the screen, so things wobble and jitter as they or the camera move. 240 is the first PlayStation's; 0 turns it off.
Affine TexturesTextures slide and bend across surfaces seen at an angle, as on consoles that couldn't correct for perspective. Big flat surfaces bend most, so build floors and walls from pieces a metre or so across.
Pixelated TexturesTextures are drawn in crisp square texels instead of being smoothed. Surface shaders' textures too.

Pair them with a post effect like the one above, set to the same number of rows, and small textures (64 pixels or so). Turning off Anti-Aliasing keeps edges as hard as they were.

When it doesn't compile

The game keeps running: a material is drawn its standard way, and an effect is left out. The Console says what's wrong and on which line of the file, such as Pixels.glsl:9: 'colur' : undeclared identifier, and the inspector of what uses it shows the same. Fix it and save, and it comes back.

Cut-outs (Alpha Clip) don't cut holes in shadows yet: a cut-out surface still casts a solid shadow.

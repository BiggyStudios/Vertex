Guide

Post effects and shaders

A post effect changes the finished picture: a colour grade, film grain, big pixels, a dithered look. You write it as a short shader in GLSL, and a Post Effect component on a camera runs it, in Vulkan and OpenGL alike.

Making one

  1. In the Assets panel, choose New Post Effect. It makes a .glsl file that starts as a simple colour grade.
  2. Select the camera, Add Component › Post Effect, and pick the file as its Shader.
  3. Its settings show below it in the inspector. Change them there, or open the file in your code editor: each time you save, the scene shows the change.

The scene view shows the game camera's post effects too, so you see the scene as the game will. The button beside the grid's in its toolbar (or View › Post Effects) turns that off and on.

A camera can have several Post Effects. They run in the order they're on it, each on what the one before made. Untick one to turn it off.

Writing the shader

A post effect is a function, effect, that's given a place on the screen and returns the colour to show there. It runs once for every pixel. This one makes the picture into big square pixels with fewer shades:

// Big square pixels and fewer shades: a low-resolution look.
property float Lines = 240 [60, 720];   // How many rows of pixels fill the screen
property int Shades = 6 [2, 32];        // How many levels each colour has

vec4 effect(vec2 uv)
{
    // Which big pixel this is, and the colour at its middle.
    float size = max(1.0, floor(screenSize.y / Lines + 0.5));
    vec2 cell = floor(uv * screenSize / size);
    vec3 colour = picture((cell + 0.5) * size / screenSize).rgb;

    float steps = float(Shades - 1);
    return vec4(floor(colour * steps + 0.5) / steps, 1.0);
}

What an effect can use:

NameWhat it is
uvWhere on the screen, from 0 to 1 across and down, starting at the top-left corner.
picture(uv)The picture so far at any place on the screen, in screen colours from 0 to 1. Lighting, fog, bloom, tone mapping and anti-aliasing have all been done.
distanceAt(uv)How far from the camera what's drawn there is, in metres along its view. Very large for the sky.
screenSizeThe size of the picture in pixels, as a vec2.
timeSeconds since the game started, for things that move.

Everything else is ordinary GLSL: functions of your own, loops, mix, smoothstep and the rest.

Settings

Each line starting with property is a setting. It shows in the inspector of the Post Effect using the shader, and the shader reads it by its name:

property float Strength = 0.5 [0, 1];   // How strong it is
property color Tint = #FFB070;           // A warm orange
property bool Flicker = false;

After the type and name come its starting value, an optional range in square brackets (the inspector shows a slider for it), and a comment, which becomes its tooltip.

TypeWritten likeIn the inspector
float1.5A number, or a slider with a range
int4A whole number, or a slider with a range
booltrue or falseA tick box
vec2, vec3, vec4(1, 0.5, 0)A box for each part
color#FF8800, or (1, 0.5, 0, 1) from 0 to 1A colour picker

A shader can have up to 16 settings. Settings changed on a Post Effect are saved with the scene; those left alone follow the shader's starting values, so changing one in the file changes every effect that hasn't set its own.

From code

Settings can change while the game runs, to fade an effect in or make it react to what happens:

var effect = Camera.Main!.GetComponent<PostEffect>()!;
effect.Set("Strength", 0.8f);
effect.Set("Tint", new Color(1f, 0.3f, 0.3f));
effect.Enabled = false;   // off for now

A Post Effect can be added in code as well: camera.AddComponent<PostEffect>().Shader = Assets.LoadShader("Shaders/Pixels.glsl").

When it doesn't compile

The game keeps running without the effect, and the Console says what's wrong and on which line of the file, such as Pixels.glsl:9: 'colur' : undeclared identifier. The effect's inspector shows the same. Fix it and save, and it comes back.
